# Лабораторна робота №2

**Тема:** розробка консольних утиліт для задач кібербезпеки.
**Варіант 12:** аналізатор заголовків електронної пошти та фішингових індикаторів.

## Установлення залежностей

З кореня репозиторію, в активованому віртуальному середовищі з ЛР №1:

```
pip install -r requirements.txt
```

Код використовує лише стандартну бібліотеку Python; із зовнішніх пакетів потрібен тільки `ruff` для перевірки стилю.

## Структура файлів

```
labs/lab_2/
├── __init__.py
├── main.py          # CLI: команди demo та analyze
├── task1.py         # Завдання 1: User, Admin, Session, AuditLog, UserAccount
├── task2.py         # Завдання 2: аналізатор поштових заголовків
├── README.md
└── data/
    ├── mail_headers.log          # вхід: дампи заголовків листів, розділені рядком "--- MESSAGE ---"
    ├── suspicious_keywords.txt   # вхід: словник стоп-слів, одна фраза в рядку
    └── phishing_report.csv       # звіт, який створює утиліта
```

## Запуск

Усі команди виконуються з кореня репозиторію.

Демонстрація Завдання 1:

```
python -m labs.lab_2.main demo
```

Аналіз заголовків листів (Завдання 2):

```
python -m labs.lab_2.main analyze --mail-log labs/lab_2/data/mail_headers.log --suspicious-keywords labs/lab_2/data/suspicious_keywords.txt --out-csv labs/lab_2/data/phishing_report.csv
```

Те саме з типовими шляхами та докладним логуванням:

```
python -m labs.lab_2.main analyze --debug
```

## Параметри CLI команди `analyze`

| Параметр | Типове значення | Опис |
|---|---|---|
| `--mail-log` | `labs/lab_2/data/mail_headers.log` | файл із дампами заголовків листів |
| `--suspicious-keywords` | `labs/lab_2/data/suspicious_keywords.txt` | словник стоп-слів для теми листа |
| `--out-csv` | `labs/lab_2/data/phishing_report.csv` | шлях до CSV-звіту |
| `--debug` | вимкнено | рівень логування `DEBUG` замість `INFO` |

Колонки звіту: `message_id, subject, score, risk_level, keyword_matches, relay_hops, reasons`.

`score` — оцінка підозрілості від 0 до 100; `risk_level` — рівень ризику: `low` (0–24), `medium` (25–49), `high` (50–74), `critical` (75–100).

## Поведінка при помилках

| Ситуація | Реакція | Код завершення |
|---|---|---|
| Не вказано підкоманду або вказано невідомий параметр | `argparse` друкує підказку | 2 |
| Вхідний файл не існує | `[ERROR] Файл не знайдено: ...` | 1 |
| Файл неможливо прочитати/записати або він не в UTF-8 | `[ERROR] Помилка читання або запису файлу: ...` | 1 |
| Словник стоп-слів порожній | `[ERROR] Словник стоп-слів порожній: ...` | 1 |
| Блок листа без `Message-ID` або `From` | `[WARNING]`, блок пропускається, аналіз триває | 0 |
| У файлі немає жодного коректного листа | `[ERROR] У файлі не знайдено жодного коректного листа: ...` | 1 |

Traceback користувачеві не показується.
